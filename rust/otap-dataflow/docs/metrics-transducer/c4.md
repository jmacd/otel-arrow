# C4. Replace gauge distributions across time

[Worklist](../metrics-transducer-worklist.md)

At boundary `b`, count the *current contributors* in each value bucket, not
the measurements received since the last evaluation. A host whose temperature
was reported ten times still occupies one bucket. Apply [C3](c3.md)'s last
eligible observation, tie order, no-data marker and event-time lookback
before projecting away host identity. This is the [gauge histogram][model]
that ordinary OTLP Histogram and ExponentialHistogram do not distinguish.

## A separately gated snapshot contract

Propose an opt-in accumulator in the new transducer executor and a versioned
Arrow intermediate type `gauge_histogram_snapshot`. In v0 the rule fixes
finite, increasing explicit bounds and the unit. Bucket intervals are upper
inclusive with underflow included in the first bucket and overflow in the
last. A row carries the output key, evaluation boundary, layout, bucket
counts, population count and signed sum of the current values. Carry writer,
rule generation, disjoint population partition and publication ID alongside
the row for validation and replacement, not as grouping dimensions.

The edge owns the last value (or absence) per contributor. Replacing a
value removes its old bucket membership and sum before inserting its new
ones. Expiration or no-data removes the old membership without inserting a
zero. Represent a known empty partition by an explicit snapshot of count 0
and sum 0. No publication from a required partition means *missing*, not
empty. The regional reader merges one snapshot per required partition at
the same boundary. A newer boundary replaces the older picture; repeated
delivery of the same publication cannot double the population. Reject
overlapping partitions, conflicting IDs or layout/unit mismatches. Mark a
cutoff with missing children incomplete rather than implying full coverage.

With bound `[0]`, two hosts at -4 and 6 give buckets `[1,1]`, count 2,
sum 2. At the next boundary the second moves to -1: `[2,0]`, count 2,
sum -5. A no-data marker for the first then gives `[1,0]`, count 1, sum -1.
The same three snapshots must result when each host has its own edge.
Neither falling bucket counts nor a negative sum signal a counter reset.
A late observation can change an open historical snapshot; it cannot roll
the live population back or rewrite a sealed snapshot.

Gate both plan binding and the inter-stage schema independently of ordinary
histogram aggregation and progressive refinement. Use the existing
[number data point view][views] for scalar input, not a new standard OTLP
metric kind or flag. Without a mutually supported snapshot encoding, reject
that output binding. V0 explicitly does not offer Prometheus text or
OpenMetrics exposition for this type: report an unsupported representation
instead of publishing `_bucket`, `_sum` and `_count` as counters. An
ordinary histogram on the same pipeline keeps its [C3](c3.md) semantics.
