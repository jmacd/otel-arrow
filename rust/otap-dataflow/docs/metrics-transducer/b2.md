# B2. Enforce replay protection before every reclaim

[Worklist](../metrics-transducer-worklist.md) | [Bookmark lifecycle](b1.md)

The deletion predicate in a bookmark store has two parts: the selected policy
permits removing this segment, **and** no bookmark covers it. Completion,
age and disk pressure may each select candidates; none can waive the second
test. Apply it before *logical* deletion too: hiding a segment from a scan
or force-completing its delivery is already observable.

## Where to enforce the predicate

1. Split [engine open][engine] into discovery/recovery and activation.
   Restore the store identity, named bookmarks and finalized segment
   inventory before any destructive scan, subscriber reconciliation, WAL
   cleanup or admission. Add durable segment-to-WAL coverage to that
   inventory; keep entries for the retained suffix and a non-reused sequence
   high-water mark. Validate required names, ranges and segment integrity.
   A filename listing cannot distinguish a legitimately empty tail from a
   missing last file. The [existing scan][store] can remove corrupt expired
   files; it must not do so on a protected range.
2. Gate completed-prefix cleanup, expiry (including startup), ingest-time
   `drop_oldest`, and periodic maintenance at selection and again at removal.
   Serialize these transitions with bookmark changes. Filter candidates
   *before* modifying subscriber state or loss counters. Enforce the same
   gate for direct segment-store unregister/delete and deferred unlink
   retries; cleanup of a partial file requires proof it was never published.
   Charge bytes until physically reclaimed. Below the bookmark floor the
   ordinary policy still applies, including its declared loss behavior.
3. Keep the WAL rule separate: sync the complete segment, its directory entry
   and covered input range before persisting a truncation cursor and purging
   rotated WAL files. A bookmark pins the resulting segment, not the WAL
   prefix forever. A not-yet-finalized accepted tail must survive replay:
   bypass the existing per-entry age filter there. Do not advance past an
   undecodable required entry or clamp an inconsistent cursor to EOF.

If no eligible deletion provides enough space, return capacity backpressure;
do not retry in a busy loop, force an ACK, or move a bookmark. Reject any
setting or storage backend that cannot honor these gates. A required file,
bookmark or accepted WAL range that fails validation stops open or live
maintenance; report the store, position and reason and preserve evidence.

## Acceptance

With `K = 42`, both 41 and 42 exceed `max_age`. With no other protection,
expiry may reclaim 41. At the disk watermark, `drop_oldest` must refuse to
reclaim 42 even with no open handles. On restart, remove 42 from the fixture:
opening must report missing segment 42, not return data starting at 43.
[B3](b3.md) also exercises replay and deferred cleanup.
