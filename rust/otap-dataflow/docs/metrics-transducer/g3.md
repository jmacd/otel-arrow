# G3. Persist, revise and merge two independent summaries

[Worklist](../metrics-transducer-worklist.md) | [Merge fixture](g4.md)

A sample describes the same accepted input cut, output group and event-time
cell as the exact delta. It is not part of metric identity. A reader must
never see a corrected point with yesterday's sketch or apply one candidate
twice because a sender retried on a new stream.

## Representation and bounds

On an opt-in E4 link, attach versioned Arrow side tables to the committed
OTAP point by its [E4 publication key](e4.md), not a batch-local row ID.
This is a proposed capability, not an existing OTLP payload type. Associate
the input cut, completeness and per-mode schema/algorithm versions with
that key; a retried publication cannot acquire a second identity.

- **Series header:** `k`, rank law/precision and seed-domain identifier,
  weight policy, allowed predicate fields, keep-all or first excluded
  rank/key, optional exact `W`. Winner rows carry original-series key,
  admitted dimensions, signed `v`, `w`, rank and stable draw or derivation
  reference. An opaque key can preserve identity without exposing removed
  dimensions; masking attributes must not collapse distinct items. These
  are aggregate-derived records, never trace links.
- **Trace header:** `m`, ordering/eligibility and representative policy,
  keep-all or cutoff pair. Winner rows carry `R`, randomness source,
  trace ID and the original exemplar time, value, filtered attributes,
  optional span ID and stable source-record key. An ordinary OTLP reader
  may receive these real measurements as exemplars, not the side tables.
  An unaware peer gets no merge or estimation capability by implication.

Reserve separate slot **and byte** budgets per mode, and cap groups, open
windows, key/attribute lengths, checkpoint/replay bytes and total memory
across cells. Charge keys, thresholds, heap/map capacity and staged output,
not just winners. The `k`-slot summary does not bound the C5 full-identity
accumulators. Reserve worst-case admitted row bytes or fail that summary
with an observable status: silently dropping large winners changes the
sampling law. Apply dimension policy before recording anything; unsupported
queries are not zeroes. A failed or disabled mode cannot borrow the other's
budget or change the recorded total.

## Revision and recovery

1. Pin replayable full input and contributor baselines, or checkpoint
   sufficient per-series aggregates and trace candidates, for the open
   correction horizon. Keep seed and derivation version recoverable; never
   choose fresh draws after recovery. Charge this state to explicit limits.
2. Apply each accepted delta once. A newer cumulative restatement replaces
   the prior cell input under E5; reject conflicting/stale publication IDs.
   Recompute a changed series rank from its original draw and new weight.
   A smaller weight, removed winner, or stale runner-up can promote an
   unseen item: rescan sufficient local state or replay the affected cell.
   The same applies to a withdrawn trace or its representative. In sealed-only
   mode reject late changes. With negotiated [restatements](e5.md), recompute
   the samples for the new revision at its new cut within the retained
   horizon; readers pinned to the original commit keep its original samples.
3. Atomically publish exact metric, summaries (or failure statuses), input
   cut, dedup state and recovery references under D2-D3 **before** moving
   the input bookmark. Retry after a lost ACK is a no-op. On recovery or
   refinement, missing required source state is an explicit gap/error, not
   a license to merge old winners. Readers at one commit see one revision.

## When a merge is valid

- **G1, disjoint series with unchanged weights:** require compatible
  identity, predicate schema, rank law/seed, interval semantics and proven
  disjoint original-series ownership. Each child must retain at least the
  requested `k` or be keep-all. Select the parent's bottom `k` from the
  union of winners, in original rank order. To find the parent's `(k+1)`st
  also include every finite child first-excluded rank/key. Anything deeper
  already has `k+1` better items in its own child. Add exact child `W` only
  under these disjointness and weight conditions. This also works across
  panes if no series occurs twice; disjoint times alone do not prove it.
- **G1, repeated series across panes/partitions:** the regional item needs
  `w = abs(sum(v))` at the target interval. Even all-positive changes can
  change the winners. Do not re-rank projected totals, add adjusted weights
  as observations, or deduplicate only the visible winners. Without the
  original contributions or complete per-series partials there is no
  general direct-sketch merge. Use the [interval options](g4.md) instead.
- **G2, fixed trace priorities:** for the same eligibility, tie and
  representative policies, union child top lists, combine by trace ID,
  choose the best representative and take the parent's top `m`. A globally
  winning ID must win in every child containing it: `m` better distinct
  local IDs would also beat it globally. This holds across panes and
  overlapping traces with unchanged `R`. Require child `m` at least the
  target or keep-all. Do not treat repeated trace IDs as new observations.

Reject incompatible or undersized partials rather than padding a result.
Private table layout and capability negotiation are open implementation
choices; provenance, separate limits, merge preconditions and atomic
publication are required regardless of encoding.
