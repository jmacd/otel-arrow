# E6. Record a metric rule written as a query

[Worklist](../metrics-transducer-worklist.md) | [Query rules RFC][rfc]

The first useful query should reproduce the F1 counter, not introduce a
second recording engine. Compile a fixed A1 rule first. Then accept a query
that selects the same points and groups them the same way. Both must produce
the same typed plan, committed OTAP metric and reader behavior. This is a
design target, not configuration accepted by today's transform processor.

## First slice: count the requests, not the lines

Use F1's DogStatsD v1.1 datagram `requests:3:4|c|#service:api`. E1 retains
the sender and ingress time at acceptance. In this fixture, both increments
belong to one UTC-aligned minute; the `service` tag is a point attribute.
Start with an empty store and a count descriptor configured for nonnegative
increments. The following is the proposed `explain` output in compact form:

```text
select requests : Sum -> resolve each writer's contributions
window (start, end], period=range=1m, origin=Unix epoch
aggregate sum by point.service -> emit requests : monotonic delta Sum
equivalent A1: select=requests, retain=[point.service], aggregate=sum,
               period=1m, output=requests, reader=cumulative
```

Seal that minute at a recorded input cut. The one cell for `service=api`
has delta `3 + 4 = 7`, not `2` (packed values) or `1` (datagrams). Two pulls
at the same commit and a pull after recovery must all read `7`. In a fresh
run, `requests:3|c|#service:api` and `requests:4|c|#service:api` in the same
minute must give the same cell. The proposed native OPL aggregate in
[E6c](e6c.md) must pass this fixture unchanged. Neither check asserts what
Prometheus `increase` would return from an arbitrary scrape history.

## What belongs to the rule

The query specifies selection, grouping and calculation. The envelope fixes
generation, UTC origin, cadence, lateness, publication policy, reader
temporality and budgets. Compile once before admitting a generation; reject
unknown constructs rather than dropping clauses. Retain the previous valid
generation on failure. Only the incremental transducer owns live baselines,
seals and commits. Start with sealed publications; richer expressions must
not acquire provisional or two-stage support without a valid merge contract.

Deliver the [typed plan](e6a.md) with the fixed-rule slice, then the
[PromQL importer](e6b.md) and [OPL/KQL lowering](e6c.md). Require each to
print its plan and equivalent A1 rule when one exists. Compare direct,
replayed and eligible staged results at the same cut and seal using
[E6d](e6d.md); two scrapes taken at similar wall-clock times are not proof.
