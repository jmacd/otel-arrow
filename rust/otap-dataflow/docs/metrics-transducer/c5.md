# C5. Reclaim state without forgetting a live predecessor

[Worklist](../metrics-transducer-worklist.md)

A rule that drops `host` can have one output and a million independent
cumulative baselines. Bound the resolver and projected accumulator
separately. D1's local evaluator owns admission; its decisions and seal
cutoffs must be reproducible by the A3 evaluator. The existing
[temporal processor][temporal] flushes early on cardinality pressure.
Flushing an exact event-time pane early would change its meaning.

## Reserve before admitting an update

- Cap live input series and output groups independently, including group
  cells per pane. At either limit reclaim eligible entries or backpressure
  new keys. Never pool raw cumulative predecessors in an overflow series.
  V0 does not silently redirect projected groups either.
- Cap the number of open panes and the observations and bytes per series.
  Keep the predecessor at the left edge, the in-horizon changes and the
  closure record if needed. If exact replay or a checkpoint can supply them,
  release cold rows. Otherwise pause admission, not the seal/control path;
  never discard just the oldest row and charge the next lifetime total.
- Bound histogram buckets per point and accumulator, including the expanded
  span between exponential offsets. Check lengths before allocating. Use the
  rule's exact [C3](c3.md) coarsening or reject an oversized layout.
- Reserve staged bytes for retained key material, Arrow buffers, pending
  batches, exemplar candidates, retry records and scratch for atomic updates.
  Charge backing allocations, not just row counts. Pause producers until
  space is freed; reject a single update that can never fit. Keep control
  and checkpoint headroom. Report the limiting budget, high-water mark and
  rejection or pause; a rejected update must not partially change a cell.

## Retire by event time, not by scrape activity

On retirement record the closure time, writer epoch and input cut in
recoverable state (or pin the input that reconstructs them). Unlink the
writer from live membership, including reverse indexes. Read bounded
historical state on demand: a late observation before closure may revise an
open pane but cannot reinsert the writer into the live population. Keep only
the predecessors, tombstones and publication IDs still needed by an open
pane or retry horizon. Once closure is sealed and replay and retry cutoffs
pass, discard those entries and index keys too. Reject older input using
the durable cutoff rather than an immortal set of retired names. Closed
output groups are reclaimed under the same recovery rule. Pinned input and
checkpoints need disk budgets too; if neither store can advance, propagate
backpressure rather than deleting the only predecessor.

Hold one service open with a stable writer contributing zero. With a
16-writer cap, admit waves of 15 distinct hosts, each adding 1 then going
absent. After every seal and retry cutoff, only the stable writer remains in
RAM; retained capacity stays bounded independent of wave count. Wave `n`'s
sealed cumulative total is `15*n` even after restart. Freeze seal progress
and exceed a cap: the recorded pressure outcome must leave earlier sealed
totals unchanged and resident state within budget.
