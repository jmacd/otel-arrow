# E3. Preserve missing starts until a series has a baseline

[Worklist](../metrics-transducer-worklist.md) | Depends on A1 and C1.

A source's creation time says when it began accumulating. The first time
a scraper saw a value says only that the value already existed. Counting
both as known zero starts can add years of requests in one scrape.

## Stateless conversion

Follow the [Prometheus timestamp mapping][mapping] per data point. Preserve
a genuine `_created` as `start_time_unix_nano`. When absent, leave the start
unset (absent column or null row in Arrow), even if other rows have starts.
Never substitute a process launch time, target discovery time or scrape time.
Apply `honor_timestamps` to the sample's **end** time as today; use the scrape
time for an untimestamped sample. That decision supplies no evidence of a
zero start. Gauges do not acquire a cumulative start through this change.

The [current scraper][scraper] captures `TargetScraper.start_timestamp_ns`
at construction. Both whole-response and chunked decoding pass it into
`records_to_otap_with_resource`; `ensure_cumulative_start_time_unix_nano`
adds a column if it is missing. Remove this fallback on both paths. Keep
genuine starts, target resource attribution and sample-time handling intact.
Do not replace it with a series cache inside the receiver.

## Stateful resolution and migration

The transducer resolves a cumulative stream under its full input identity
and writer epoch *before* grouping. On the first missing-start sample at T
with value V, record `(start=T, end=T, value=V)` as an [unknown-start
baseline][unknown]. This zero-duration observation contributes no increase;
it does not assert that V is zero. Keep T as the start of this sequence and
difference subsequent compatible observations against the saved predecessor.
Persist the epoch, baseline and predecessor at the checkpoint's input cut.
An incoming delta already describes a contribution: do not discard its
first value this way.

Consumers that previously treated all scraped counters as having known
starts must now handle absence or select the stateful resolver. Do not mix
old, synthetic starts with the new policy mid-epoch. At an upgrade boundary
either restore demonstrably compatible baseline state or begin a new rule
generation with fresh baselines; leave earlier published history unchanged.

## Acceptance timeline

- One receiver runs all morning. Host A first reports 900 at 10:03 with
  no start; host B first reports 42 at 10:47 with no start. Stateless
  output has two absent starts. Stateful baselines are 10:03 and 10:47,
  respectively, not a common receiver timestamp. A later A sample of 907
  contributes 7, even after restarting the scraper and restoring evaluator
  state. Replaying the same cut produces the same 7.
- In the same decoded batch, host C reports 5 at 10:47:30 with a genuine
  `_created` of 10:47:10. Its known-start interval contributes 5. A stays
  missing on the wire. When C next reports 2 with a verified new creation
  time after the last sample, take 2 in the new epoch, never `2 - 5`.
  A decrease in a non-monotonic sum alone is not evidence of such a reset.
