# D3. Publish one checkpoint, then release its input

[Worklist](../metrics-transducer-worklist.md) | [Checkpoint fields](d2.md)

The instance writer serializes commits per rule group. Only the durable
checkpoint head, not a segment callback, directory listing or downstream
ACK, publishes an evaluation. While building the successor of `P`, keep
the old head, its dependencies and the old input bookmark intact.

## Write order

1. Journal an [A2](a2.md) evaluation decision in the accepted input log:
   boundary, data frontier, source progress, seal and missing coverage.
   The marker's ordinal ends the cut `C`. Persist it using [D1](d1.md)'s
   admission barrier before acting on it, including timer-driven idle seals.
   Input arriving after the marker belongs to a later cut.
2. Apply unapplied records through `C`. Stage every public OTAP bundle and
   private state object, then the immutable manifest for `P+1`. Sync the
   files and their directory entries; verify references, covered ordinals
   and that the old bookmark still protects all required raw ranges. Stage
   objects under distinct IDs so a retry cannot overwrite a published file.
3. Write and sync a small checked head naming that manifest. Atomically
   replace the prior head on the same filesystem and sync its parent. Only
   then expose `P+1` via the in-memory reader catalog. No reader discovers
   work by scanning staged files. After an ambiguous rename/sync error stop
   publication and GC; recover under the namespace lock.
4. Durably advance [the bookmark](b1.md) to the manifest's `K`. Failure
   here retains excess input; retry idempotently without re-emitting cells.
   Collect only objects unreachable from current recovery, retained public
   history and active reads. Use the reserved working space, not space
   assumed reclaimable after the advance.

## Reopen before admitting input

Restore bookmarks with cleanup disabled. Select the validated, published
head, not the largest numbered candidate. Validate all required references;
a corrupt published head is not permission to fall back past released input.
An older pin is safe; a pin ahead of the required `K` is a recovery error.
Load materialized private state and rebuild only explicitly referenced ranges
at or before `C`. Then apply `(C, accepted-through]` in log order, including
recorded decisions, without evaluating historical lateness against today's
clock. Recover initial state only from a proved fresh namespace. Reclaim
proven staging orphans only after validation, before reserving another try.

Reuse [Quiver WAL replay][engine] and [segment writing][segment]; add strict
ordinal/coverage checks across finalized segments and rotated/active WAL.
Skip overlap only for identical already-covered records. An incomplete frame
strictly beyond the durable accepted frontier is unaccepted; discard such
staging only after validation. A missing, conflicting or unreadable required
record stops recovery, retaining evidence. Rebuilt publications use the
original keys; retries on a link are not new evaluations ([E4](e4.md)).

## Crash acceptance

Start at `P=11`, total 5. Journal a delta of 7 and its seal. Interrupt
immediately before and after each sync, head replacement and pin advance.
An old head exposes 5 and recovery produces `P=12` once; a new head exposes
12 with exactly one delta of 7. A crash between rename and directory sync
may reopen either complete head. After a successful directory sync it must
reopen 12, even with the old pin. No response may mix tables from both; no
restart may publish a second delta or turn a missing segment into a zero.
