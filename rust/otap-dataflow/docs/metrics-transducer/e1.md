# E1. StatsD codecs and paired UDP nodes

[Worklist](../metrics-transducer-worklist.md) | Depends on A1.

An edge should be able to record a datagram now, decode it tomorrow, or
relay it unchanged without ever decoding it. Those are different promises:
recording must preserve the observation; a relay must preserve the wire bytes.

## Transport and storage

Propose two metrics-only [codec registrations][registry]: `statsd` for
plain StatsD and `dogstatsd-v1.1` for the DogStatsD v1.1 metrics grammar.
Select the encoding per listener or destination, not by inspecting the line.
The [pipeline binding][codecs] selects the decoder and encoder.

`receiver:statsd` listens on UDP only, not TCP or Unix sockets. Admit each
datagram as one metrics bytes payload. Capture ingress time and sender
endpoint once at receipt; persist both alongside the encoding and unchanged
bytes. Bind this metadata to the original datagram even across queued work,
batching and replay. The [decoder interface][decoder] takes signal and bytes.
The proposed integration passes the captured observation alongside the bytes
at materialization; the raw-store adapter restores the same pair on replay.
Until batching can retain that association per datagram, keep one datagram
per payload. Do not read the clock in the decoder or add headers on the wire.

`exporter:statsd` follows the UDP path of the [proposed syslog exporter][tx]:
forward matching encoded datagrams directly when the binding permits;
otherwise request the selected wire representation from the codec service.
Never transmit local ingress metadata. Enforce a datagram byte cap even on
passthrough. Packetize new output on whole-line boundaries; reject a single
oversize line. Bound socket queues and batches; count observed truncations,
drops and send errors. A successful send confirms local transmission only.

## Measurements, not precomputed windows

Start with counters. In plain StatsD, `c` supplies an increment for a
delta Sum, `ms` a timer observation in milliseconds, `s` a set member and
`g` an absolute assignment or signed relative update. An additive level and
a temperature both use `g`; configure the metric name's meaning and unit.
Plain StatsD has no tag field or packed numeric lists. DogStatsD adds `h`
and `d` for histogram and distribution samples, and tags such as
`#service:api` for point attributes. Start with names containing letters,
digits, underscores or periods. Reject unrepresentable names, units,
attributes or types on encode; do not strip labels or reconstruct imaginary
samples from an aggregate histogram.

The codec parses and serializes measurements, retaining sender, order and
update kind on materialization. An untimestamped increment belongs to the
window containing its ingress time; only the evaluator emits an aggregate
with that window's `(start, end]`. The evaluator, not a socket or codec,
maintains per-source gauge levels, histogram buckets and bounded set
membership. The captured sender distinguishes sources under the configured
identity mapping; it is not an authenticated or durable writer ID.

In particular, `+2|g` needs a previous level and a set member is not a
cardinality. Specify how the consumer receives those operations before
enabling them for native conversion; a stateless decoder must not pass off
`+2` as an absolute gauge or emit `1` as the distinct count. Matching-byte
relay and the counter-only demonstration do not depend on those mappings.

Before claiming [v1.1 metrics][dog], cover `c`, `g`, `ms`, `h`, `d` and `s`;
events, service checks and later extensions are out of scope. For numeric
types a packed line equals successive single-value lines in wire order.
Resolve tags once; apply any eligible sample rate per value. Keep the
single-value fast path. `s` has one literal member, even if it contains a
colon. Bound line length, tags and packed values before applying any update.

## Acceptance examples

- Relay `requests:3|c` and, on the DogStatsD listener,
  `requests:3:4|c|#service:api`. Compare each outbound datagram byte for
  byte, including any final newline. Separately encode representable OTAP
  increments, send over UDP and decode: expect 3 without attributes, or
  7 for `service=api`. Replaying the stored input uses its original time
  and sender, not those of the relay.
- Following the [packed parser fixtures][packed], `n:3::4|c|@0.5` adds
  `6 + 8`; `level:10:+2:-3|g` ends at 9. An all-empty list, `n:3:oops|c`
  or `n:3:NaN|c` reports a parse error and applies none of the line.
