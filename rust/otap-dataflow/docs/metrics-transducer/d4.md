# D4. Read a snapshot, read history, or follow from the same commit

[Worklist](../metrics-transducer-worklist.md) | [Publication barrier](d3.md)

An as-of token identifies a published commit `P` in one instance, writer and
rule-group generation. A cell belongs to its recorded event-time window;
`P` says which version is visible, not when to start a new window. Serve
all reads from the public objects indexed by [D2](d2.md), never by running
the live evaluator a second time.

## Reader operations

- **Snapshot/range:** resolve "latest" to one `P` at request start. Pin its
  immutable public view for a bounded read. Return the latest sealed values
  or a requested range of window ends as of `P`, plus the token and seal.
  A no-data marker denotes absence, not zero. A cumulative view uses the
  recorded output epoch starts and closures; a delta view uses committed
  interval contributions. Maintain a cumulative base at the history floor
  so eviction of old deltas does not reset a live epoch. Reading a range or
  encoding a [scrape](e2.md) changes no cursor.
- **Follow after `P`:** install a named, durable cursor at `P` while checking
  the retained range under the writer. To read-history-then-follow without a
  race, install it when acquiring the as-of token; later commits queue by
  position, not by whether a notification was observed. Deliver `P+1` onward
  in order. The cursor is the highest contiguous commit accepted by this
  reader's destination. Advance it durably only after every publication in
  the commit is acknowledged; seal-only commits carry progress as needed.
  A lost ACK or restart retries the same [publication keys](e4.md), never
  another reader's cursor. A transport ACK alone does not establish remote
  durable acceptance on a regional link.

Quiver already has [per-subscriber delivery progress][progress]. It does
not provide this as-of catalog, pinned history-to-follow handoff, or ACK
of a complete checkpoint. Have the single writer persist cursor changes;
readers own only bounded batches, leases and outstanding attempts.

## Retention and gaps

Keep the last configured `H` commits plus all commits strictly after each
durable follower's ACK. Reject budgets that cannot fit `H` bounded commits
and the next commit's working space. Bound readers, leases, response bytes
and lag. Release snapshot leases on completion, cancellation or deadline.
If a disconnected follower prevents reclamation at its limit, pause new
publication and backpressure admission; continue to serve retained reads,
ACKs and catch-up. Do not spend the checkpoint reserve to queue more data.
Only explicit retirement may abandon that follower's unacknowledged suffix.
When requested history has expired, return a gap with requested and earliest
available position/window and current head. Never silently truncate a range
or skip to latest; resnapshotting is a caller decision.

## Acceptance

With one epoch, commits 20 and 21 contain deltas 3 and 4. Acquire `P=21`
and register follower X there. Two pulls at 21 return 7, including after 22
publishes delta 2. X follows with 2; follower Y at 20 independently receives
4 then 2. Restart before X's ACK is durable: X retries 22 with the same key.
After retirement and expiry, asking for 20 reports a gap, not 9.
