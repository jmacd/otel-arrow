# G2. Keep trace links that survive higher sampling thresholds

[Worklist](../metrics-transducer-worklist.md) | [Checkpoint and merge](g3.md)

The population is the **distinct traces in supplied, eligible measurement
exemplars** for a rule group and interval. A large measurement must not
outrank a small one. A trace need not represent a typical host, request or
delta. This is a drill-down list, not a way to estimate metric totals.

## Establish the trace's randomness

Require a valid, nonzero 16-byte trace ID. Preserve an optional valid
nonzero 8-byte span ID as supplied; do not synthesize one. Use the same
unsigned 56-bit randomness `R` used by the trace's consistent sampler:

1. Prefer the explicit `ot` tracestate `rv` (14 lowercase hex digits) if
   legitimately supplied by a trusted producer for **this** trace, e.g.,
   from its captured SpanContext via a negotiated extension. Ordinary
   [OTLP exemplars][exemplar] carry no tracestate or random-ID flag. A
   filtered attribute named `rv`, the point's context or the collector's
   current span is not evidence of trace randomness.
2. Otherwise, use the **least-significant** 56 bits of the trace ID: read
   the last seven bytes in network order. Use this fallback only for a
   source known to use suitably random trailing bits as `R` (no differing
   explicit override). Do not use the first seven bytes, hash the ID, or
   infer randomness from how the hex string looks.
3. Without either contract, omit the link and count the reason. Reject
   malformed explicit context rather than silently falling back. An empty
   G2 reservoir with a populated [G1 sketch](g1.md) is normal. Whether to
   offer a separately labeled best-effort link list is an open policy; it
   must not claim consistent sampling.

## Fixed threshold versus fixed space

For uniform `R` in `[0,2^56)`, a **fixed** rejection threshold `T` keeps
`R >= T` with probability `(2^56 - T) / 2^56`. Raising `T` gives a nested
subset. Prefer large `R` because those links clear stricter consistent
thresholds, not because a backend has promised to store the trace. Prior
filtering and tail sampling can change which exemplars are available.

With a budget of `m >= 1` traces, keep the `m` **largest** `R` values.
Break equal `R` by smaller full trace ID (unsigned byte order). If all fit,
the cutoff is `T = 0`, including when there are exactly `m`. Otherwise the
adaptive boundary is the `m`th best **included** pair: keep greater `R`,
or equal `R` and ID no greater than the boundary ID. Persist the pair and
the keep-all flag. `R >= cutoff.R` alone can exceed the budget at a tie.
This order statistic is neither a fixed sampling probability nor the G1
inclusion probability. Do not export it as a trace's `th`.

Use a heap plus a map of its resident trace IDs. A repeated ID has one
priority and consumes one slot. Keep its earliest measurement, then the
smallest span ID (absent first), then the least stable source-record key
to resolve ties. The key must survive rebatching; metric value is never a
selection key. Carry that representative's original measurement time,
typed value, allowed filtered attributes and trace/span IDs together. If
two ranks for the same trace conflict, the source contract is broken; do
not merge them as two traces. A correction or withdrawal may require a
rebuild, not just another heap insertion.

## Acceptance fixture

Three trace IDs have distinct nine-byte prefixes `01`, `02`, `03` (each
left-padded to nine bytes) and seven-byte suffixes `f0000000000000`,
`80000000000000`, `80000000000000` respectively. With valid ID-based
randomness and `m = 2`, keep IDs 01 and 02; 03 loses the tie. A fixed
`T = 0x80000000000000` admits all three, `T = 0xc0000000000000` only 01.
Retry 02 and multiply 03's metric value by 100: neither changes membership.
In a separate run, give 03 trusted `ot=rv:ff000000000000`: 03 and 01 win.
As an ordinary exemplar from an unverified ID source, 03 is ineligible.

See [OTel consistent sampling][sampling] for `R` and `T`, and
[Ting's adaptive thresholds][ting] for the fixed-space distinction.
