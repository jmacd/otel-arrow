# B1. A durable, inclusive replay bookmark

[Worklist](../metrics-transducer-worklist.md) | [Deletion rules](b2.md)

A bookmark answers "which input must still exist if this consumer restarts?"
It does not answer "which bundle should I deliver next?" For a bookmark at
segment `K`, Quiver must keep **every finalized segment from K inclusive**,
including segments finalized later. The unit is a whole segment even when
only its last bundle is needed. The bookmark holds no Arrow arrays or file
handles. It belongs to a named consumer, initially one per independently
recoverable rule group; Quiver need not know what a rule is.

## Lifecycle under the store writer

- **Create:** serialize registration with finalization and cleanup. Validate
  the name and store identity; accept an intact suffix of the retained log
  or its next segment position, never a guess past missing history. On a
  fresh store `K = 0` protects the first segment before it exists. Persist
  registration before admitting input for that consumer or enabling cleanup.
  On restart reattach by name and generation; never reset to today's head.
- **Read:** scan immutable segments by `(segment sequence, bundle index)`.
  Reuse [`BundleRef`][ref] and the [segment provider][provider] for
  reconstruction. A scan cursor may move ahead, be dropped, or seek back to
  `K`. Resolving a [delivery handle][handle] affects only that subscriber;
  neither resolving it nor dropping reconstructed data changes `K`.
- **Advance:** only the owner may move `K` forward, no further than the next
  segment position. Repeating the same advance is a no-op; reject rewind.
  The caller must first make recovery without the released prefix durable
  ([D3](d3.md)). Ordinary cleanup uses the minimum of all live bookmarks and
  all ordinary subscribers' outstanding needs. With bookmarks alone it may
  reclaim below their minimum, never the segment at the minimum.
- **Retire:** require an explicit owner decision that recovery is no longer
  required. Disconnection, dropping the last reader, or omission from a new
  configuration is not retirement. Reject stale advances after retirement or
  re-creation under a new registration generation.

Add a bounded, versioned registry of names, generations and positions tied
to the store ID. Replace it atomically under the writer: write and sync a
checked temporary file, rename, then sync the directory before allowing GC
to use weaker protection. On restart restore it, not a subscriber's progress
bitmap. A missing registry in an initialized bookmark store is an error.
[`quiver.sub.*` persistence][progress] is a format precedent, not this API.

## Acceptance

Pin 42, read and ACK deliveries through 90, then close every handle. A fresh
scan after restart must still return bundle zero of 42. Advance to 43:
42 is now eligible only if no other bookmark or subscriber needs it. See
[B3](b3.md) for the interrupted-update cases.
