# D1. One writer, one evaluator, two stores

[Worklist](../metrics-transducer-worklist.md) | [Checkpoint format](d2.md)

Use one new metrics-only DFE processor on one local pipeline core. Its input
port admits observations; its timer drives evaluation. `quiver_ingest` owns
the raw accepted log and replay bookmark. `metrics_checkpoints` owns immutable
result bundles, private recovery state and their published manifest. A pull
endpoint requests a committed snapshot; a push reader sends committed deltas
to the downstream exporter. Neither reader opens a second writer or drives
the evaluator ([D4](d4.md)).

## Namespace and admission

Give each instance an explicit stable ID, not a PID, core index or deployment
order. Under the [engine state directory][root], open an instance namespace
with these two named children; persist their identities together. Edge A and
region B have distinct namespaces and writer identities. Hold an exclusive
OS lock on the instance for its full lifetime, including startup recovery.
On Linux use the [validated directory descriptor][cap] with constrained,
no-follow descendant opens. Quiver's current path-based open needs adaptation.
Reject missing capability, unsupported platform, duplicate writer or partial
namespace; never silently provision replacement stores on restart.

Extract the [durable buffer's][buffer] OTAP bundle adapter and ingestion
pattern, not its forwarding queue or an extra buffer node. Add an envelope
with store-scoped input ordinal, original timestamps and writer identity,
codec context (e.g., StatsD arrival time/sender), and any publication key.
For encoded inputs, persist the signal, encoding ID and original bytes with
that context in a raw record; an OTAP-only conversion at admission would lose
the [E1](e1.md) datagram. This record and its replay adapter are new work.
Preserve these across WAL replay and segment finalization. Serialize
admission, including control records. ACK a batch only after its WAL frames
and new file entries are synced and a durable accepted-through frontier
covers it. Use a bounded group sync; the [WAL writer][wal] has a flush
barrier internally, but successful buffered `ingest` is not that receipt.
Do not finalize or publish an unaccepted suffix. For a regional publication,
the key, digest and contribution must be recoverable together before ACK
([E4](e4.md)); an ordinary unkeyed retry has no such dedup guarantee.

## Capacity and scheduling

Size a hard instance quota for both stores. Before accepting raw input,
reserve space unavailable to raw traffic for a worst-case bounded checkpoint
alongside the current one, input WAL rotation and segment finalization, and
control, manifest, cursor and directory updates. Charge temporary files,
retained history and physical files awaiting deletion. Enforce size bounds
on the *next* batch, not just current usage. Quiver's [watermark][budget]
is not a filesystem reservation: use provisioned capacity and stop intake
if free space or its guaranteed allocation cannot cover the reserve. Reject
configurations below Quiver's WAL-plus-two-segments minimum or lacking this
additional headroom.

Arm the timer at startup. Flush short segments and process [A2](a2.md)
progress/cutoff decisions even with no next packet. Limit bytes, rows and
pending I/O per turn; offload blocking filesystem work, yield between
chunks, and keep one ordered writer. Stop intake on shutdown, finish bounded
sync/commit work, then release the lock once no I/O can still mutate a store.
At deadline leave the last durable commit and retained WAL for
[recovery](d3.md); do not report pending ACKs.

## Acceptance

ACK an isolated delta of 7, stop before segment finalization, and reopen A.
B cannot open A as a second writer. With no further input an explicit timer
cut seals the recovered 7 once. Fill A to its raw admission ceiling: the
next raw batch is backpressured, but a bounded checkpoint still fits.
