# C2. Add changes within an output epoch

[Worklist](../metrics-transducer-worklist.md)

The rule's `Aggregate` sums [resolved changes](c1.md) by projected identity
and pane. Both Counter and UpDownCounter are additive across sources; only
the former promises nonnegative changes. Keep integer arithmetic checked and
signed where required. Reject a negative Counter delta. Declare the numeric
contract for finite doubles: bit-for-bit staging requires a reproducible
accumulator and sufficient intermediate precision; an ordinary floating sum
needs a documented error bound for the [A3 comparison](a3.md). Reject an
exact forwarding request when the representation loses required precision.
Never wrap, clamp a negative change to zero, or mix incompatible descriptors.

## Level, change and fresh start

An UpDownCounter observed at 7 then 4 in one source epoch has current level
4 and interval contribution `4 - 7 = -3`. If a second writer changes by +2
in the same pane, the group's delta is -1. Differences cannot establish an
unknown opening level: an edge that sent only the 7 from 900 to 907 did not
send 900. Do not label its regional change total as the source's lifetime
level.

The transducer is the single writer for each output identity and generation.
A delta reader gets the pane change with pane timestamps. In an output epoch
starting at `B`, its cumulative reader gets the prefix sum of admitted
changes on `(B,t]`, with start `B` on every point. Neither representation
depends on how often it was read. Keep input baseline values and their
timestamps separately from that output accumulator.

For example, finish an output epoch at boundary `B` with total 100. Two
continuing counters read 40 and 60 there. Record those predecessors, close
the old epoch, and start the next accumulation at zero. When they reach 43
and 62, its first cumulative point is `(B,t,5)`, not 105. The old 100 is
still readable. No input reset occurred. If a contributor has no sample at
`B`, do not invent one: [C1](c1.md) rejects a difference straddling `B` and
retains the next observation for future changes. Checkpoint the output start,
prefix and source baselines together; a reader reconnect is not a new epoch.

## Absence is not a final number

Inspect [`no_recorded_value()`][flags] before the value. Such a point marks
the named series absent at its event time. Ignore even an encoded numeric
placeholder. End that contributor's live membership, not its accepted
history; other writers can keep the group live. Emit `NO_RECORDED_VALUE` for
an output when that named output becomes absent, not once for every departing
input. Never subtract a departing counter's lifetime total.

If a last value of 4 must be published, send a valued 4. A separate opt-in
final-value indication would need its own negotiated meaning; neither the
no-value mask nor the RFC's refinement mask means "final valued point."
Replaying the valued point followed by absence must preserve the earlier 4
and expose absence, not zero, afterward. Put these transitions in the new
transducer executor from the [rule plan][plan], not the existing timer flush.
