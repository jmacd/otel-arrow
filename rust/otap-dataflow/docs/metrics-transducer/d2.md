# D2. A versioned checkpoint names a complete evaluation

[Worklist](../metrics-transducer-worklist.md) | [Commit protocol](d3.md)

A checkpoint is the recovery image of one rule group, not a scrape cache.
The writer builds it from exactly one accepted input prefix. Give its
manifest a magic, format version, length and checksum. Name immutable
objects by store-relative ID, length, schema version and digest. Validate
these fields and configured count/size limits before decoding Arrow data.

## Coordinates in the manifest

- **Identity:** instance and both store IDs, logical writer and generation,
  rule group/generation, effective [rule plan](a1.md) and schema fingerprint.
  A semantic change needs a new generation or a checked migration.
- **Cut `C`:** inclusive logical ordinal processed in the input store, with
  an explicit before-first value. It includes accepted input and ordered
  control records, independent of how WAL frames become segment bundles.
  Record evaluation boundary, sealed-through `S`, source progress, decision
  cut and completeness (including missing children). Evaluation can advance
  while `S` stays put; an idle seal can advance `S` without another sample.
- **Keep-from `K`:** earliest whole segment needed to restore any referenced
  input or resume at the first unprocessed record. Name exact ranges for
  rebuilds; `K` is not "the segment after `C`". If recovery needs no older
  data, the next segment may be pinned before it exists ([B1](b1.md)).
- **Output position `P`:** monotonic commit number scoped to writer/group
  generation, with predecessor and the ordered range of public bundles
  introduced at `P` (possibly empty). Persist stable publication keys, not
  stream attempt IDs. Reader ACK cursors are not part of evaluator state.

## Sections and lifetime

The public section identifies complete recorded OTAP bundles with all their
dependent tables, event-time windows and epoch semantics for [D4](d4.md).
Separately encode private Arrow batches keyed by full contributor identity:
predecessor, epoch and start status; active windows and retained edges;
output epoch starts, totals and closures; accepted publication keys, digests
and retry floors. Use a materialized value **or** a bounded recipe naming
retained input and control ranges, never both as additive contributions.
For query plans the [RFC][rfc] specifies `GroupsAccumulator` partials; index
their Arrow state by plan node, schema and group key, not transient runtime
indices. When refinement is enabled, include per-cell revisions and child
contributions. None of these private rows are exported as metrics.

Reuse Quiver's [bundle abstraction][bundle] and immutable segments for
payloads, not its delivery-based garbage collection. The multi-object
manifest and private schemas are new work.
Bound live state, history, retained raw references and staging together
([C5](c5.md), [D1](d1.md)). Old public snapshots need not keep superseded
private baselines alive. Unknown versions, missing references or identity
mismatches prevent resume; never infer baselines from published totals.

## Acceptance

At `P=8` checkpoint unknown-start hosts A=900 and B=10 after establishing
both baselines. Reopen, observe A=907 and B=13 in the same epochs and seal.
`P=9` must contain one service delta of 10; the private host values must
not appear in either reader. A reader fixed at `P=8` sees neither update.
