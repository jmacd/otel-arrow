# E6d. Compare recorded cells with a bounded query-time scan

[Worklist](../metrics-transducer-worklist.md) | [E6](e6.md)

Build a read-only DataFusion executor for verification, not a second writer,
public query endpoint or fallback on the ingestion thread. Given a typed plan
and committed result position `P`, answer: which sealed cells should exist
under that generation at input cut `C` and sealed-through boundary `S`? The
expected answer must not depend on when the scan happens to finish.

## Pin the comparison before scanning

Open one manifest at `P` naming the generation, plan/schema version, `C`,
`S`, input coverage, and the admission, seal and revision decisions visible
there. Acquire bounded read leases on both stores before exposing the scan:
retained [Quiver] input up to `C` (including predecessor history or a
validated starting baseline) and committed results as of `P`. Never include
the live WAL past `C`, newer restatements or unpublished checkpoints. Missing
history, an expired commit or lease, and a corrupt segment are failures, not
an empty series or permission to read the latest commit.

Expose these views through separate `TableProvider`s. On the input side
lower the plan to a `LogicalPlan`: filter, order by full contributor/epoch
and event time with deterministic ties, resolve intervals, assign panes, then
aggregate and finalize. Honor recorded acceptance and finality, not today's
clock. Do not use the target commit's aggregate as the answer. On the result
side materialize the corresponding cells and phases at `P`. Compare keyed
multisets, including absence, timestamps, unit, type, coverage/completeness
and value. Keep duplicate multiplicity; specify float tolerances per plan.
Report a bounded sample of mismatches with key, expected, actual and cut.

## Run within a budget

Use a bounded verification worker queue; DataFusion execution and its
`Send + Sync` interfaces stay off the local recording runtime. Cap concurrent
jobs, pinned bytes and lease duration, scanned rows/bytes, memory, partitions,
spill space and returned cells. Reserve resources before pinning. Report
progress in segments, rows and last completed boundary; check cancellation
and deadlines between bounded batches and during expensive sorts or merges.
On exhaustion or shutdown cancel, release both pins and scratch space, and
report an unfinished comparison. No scan advances a recovery bookmark, ACK
cursor or seal. Follow the [runtime progress guidance][progress].

## An independent check on both executors

A3 supplies small fixtures with hand-derived cells and explicit seal events,
not goldens generated by either executor. F1 expects one `service=api` cell
of `7`. An unknown-start cumulative `900` followed by `907` in the next pane
contributes `7`, not `907`; place both observations on the pane boundaries.
Check the scan and incremental commit separately against those answers, then
compare direct, restarted and eligible two-stage results at matched cuts.
Start a scan at `P`, commit more input, and require the answer still be for
`P`. Cancel a paused scan and verify that ingestion, ACK and shutdown make
progress and no lease remains.

An optional Prometheus differential check is narrower still: run only
expressions and fixtures with the same sample, time, label and staleness
semantics on both sides, as specified in [E6b](e6b.md).
